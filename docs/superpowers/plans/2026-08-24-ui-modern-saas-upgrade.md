# Modern SaaS Dashboard UI Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the `apps/web` design system (tokens + `Button`/`Card`/`Badge`/`StatCard`/`DataTable`) and `AppLayout`/`DashboardPage` more visual depth and polish — gradient accent chips, tinted elevation, trend pills, a sticky/hover-polished table, a refreshed sidebar/topbar, and a small chart on the dashboard — while staying inside the existing Blue+White brand theme, with zero new npm dependencies.

**Architecture:** Eight files change, each independently testable. `index.css` gains four `--color-*-border` tokens (auto-generate `border-success-border` etc. utilities, same mechanism as the existing `--color-success-light` tokens) and one plain `--gradient-primary` custom property (consumed only via inline `style`, not a Tailwind utility, since it's a gradient value, not a solid color). `Badge`, `Button`, `Card` get additive visual changes with no prop/signature breaks except `Card` gaining one new optional `interactive` prop. `StatCard` is the first (and in this plan, only) consumer of `Card`'s `interactive` prop and of `--gradient-primary`. `DataTable` gets a sticky header and softer row hover. `AppLayout` gets a left-accent active nav state, a shadow-based topbar, and a small avatar. `DashboardPage` gets a gradient hero strip and replaces a plain list with a `recharts` horizontal bar chart (recharts is already a dependency; this is its first use in the app) built from the exact same `data.operations.stockCountStatus` field the API already returns — no backend change.

**Tech Stack:** React 19, TypeScript, Tailwind CSS v4.3.3 (`@theme` tokens), `lucide-react`, `recharts` 3.10.1 (already installed, first use here).

## Global Constraints

- Design exactly as specified in `docs/superpowers/specs/2026-08-24-ui-modern-saas-upgrade-design.md`. Stay inside the existing **Blue + White** theme (`plan.md` §67) — no new brand colors, no dark mode.
- **No new npm dependencies.** No `framer-motion` — all motion is CSS transitions/transforms (confirmed with user during brainstorming).
- **No backend/API changes.** The dashboard chart in Task 8 must be built only from `DashboardSummary.operations.stockCountStatus`, which the API already returns (`apps/web/src/types/entities.ts:206-232`).
- **No changes outside the 8 files listed below** — other pages inherit the upgrade automatically by reusing these shared components; do not touch page-specific files.
- UI copy stays Thai; identifiers/types stay English (project `CLAUDE.md`).
- No component test runner is configured for `apps/web`. Verification per task is: `cd apps/web && npx tsc -b && npm run lint`, plus a manual browser check via `npm run dev:web` (do not introduce a test framework).
- **Verified Tailwind constraint (found during planning, empirically tested against this exact project's Tailwind 4.3.3 build):** arbitrary shadow values containing comma-separated function arguments — e.g. `shadow-[0_4px_12px_-2px_rgba(37,99,235,0.25)]` — silently fail to generate any CSS in this project's build (confirmed via direct build output inspection). **Do not use that pattern.** Use Tailwind's native colored-shadow utilities instead (e.g. `shadow-md shadow-primary/25`), which were verified working and are used throughout this plan.
- Every new/changed Tailwind class used in this plan (`border-success-border`, `bg-gradient-to-br`/`bg-gradient-to-r`, `from-primary`/`to-indigo-600`, `from-primary-light/40`, `shadow-primary/25`, `active:scale-[0.98]`, etc.) was empirically verified to compile correctly in this project's exact Tailwind 4.3.3 + Vite setup before being included below — no further exploratory spikes should be needed.

```tsx
import type { LucideIcon } from 'lucide-react'
import { TrendingDown, TrendingUp } from 'lucide-react'
import { Card, CardBody } from './Card'
import { cn } from '@/utils/cn'

interface StatCardProps {
  label: string
  value: string
  icon?: LucideIcon
  trend?: { value: number; label?: string }
  tone?: 'default' | 'success' | 'warning' | 'danger'
}

const TONE_ICON_CLASSES: Record<NonNullable<StatCardProps['tone']>, string> = {
  default: 'text-white',
  success: 'bg-gradient-to-br from-green-400 to-green-600 text-white',
  warning: 'bg-gradient-to-br from-amber-400 to-amber-600 text-white',
  danger: 'bg-gradient-to-br from-red-400 to-red-600 text-white',
}

export function StatCard({ label, value, icon: Icon, trend, tone = 'default' }: StatCardProps) {
  const isPositive = trend ? trend.value >= 0 : false
  const TrendIcon = isPositive ? TrendingUp : TrendingDown

  return (
    <Card interactive>
      <CardBody className="flex items-start justify-between gap-3">
        <div className="flex flex-col gap-1">
          <span className="text-sm text-text-secondary">{label}</span>
          <span className="text-2xl font-semibold text-text-primary">{value}</span>
          {trend ? (
            <span
              className={cn(
                'inline-flex w-fit items-center gap-1 rounded-full px-2 py-0.5 text-xs font-medium',
                isPositive ? 'bg-success-light text-success' : 'bg-danger-light text-danger',
              )}
            >
              <TrendIcon className="size-3" />
              {isPositive ? '+' : ''}
              {trend.value.toFixed(1)}% {trend.label ?? ''}
            </span>
          ) : null}
        </div>
        {Icon ? (
          <span
            className={cn('flex size-10 shrink-0 items-center justify-center rounded-lg shadow-sm', TONE_ICON_CLASSES[tone])}
            style={tone === 'default' ? { backgroundImage: 'var(--gradient-primary)' } : undefined}
          >
            <Icon className="size-5" />
          </span>
        ) : null}
      </CardBody>
    </Card>
  )
}
```
